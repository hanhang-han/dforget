# 智能提醒 App — 温度设计规范

> 版本：v1.0 | 2026-05-06
> 定位：极简是骨架，温度是灵魂。温度不靠视觉装饰，靠内容本身。
> 关联文档：`remind-app-ui-design.md`（v2.0 极简版）· `remind-app-scenarios.md` · `remind-app-feedback.md`

---

## 一、温度的定义

### 什么是"有温度"？

**不是**：卖萌、颜文字、鸡汤、过度亲切（"亲爱的用户"）、拟人化过度（"我是你的小助手~"）

**是**：像一个熟悉的朋友在恰当的时候说了恰当的话。不多不少，不刻意不做作。

### 温度的三个层次

```
第1层：不说废话    — "22°C，多云转雨" 改为 "下午有雨，带伞出门"
第2层：语境感知    — 工作日下雨 vs 周末下雨，文案不同
第3层：适时关怀    — 偶尔多一句，但绝不啰嗦
```

### 温度红线

| ❌ 不要做 | 原因 |
|-----------|------|
| "亲爱的""小主""亲" | 刻意讨好 |
| 💗✨🌸🎉 大量 emoji | 低幼感 |
| "你是最棒的！""加油鸭！" | 空洞鼓励 |
| 每条都带感叹号 | 情绪过度 |
| 反复说同样的话 | 机械感 |
| 打断用户思考 | 不尊重 |
| 道歉式表达 "对不起打扰了" | 过度卑微 |

## 二、文案温度策略

### 2.1 核心原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **像朋友说话** | 自然口语，不用书面语 | ❌ "今日降水概率85%" → ✅ "下午有雨" |
| **说人话** | 不堆数据，只说结论 | ❌ "当前气温较昨日下降5°C" → ✅ "比昨天冷了，加件外套" |
| **看场合** | 同一个事，不同时间/场景不同说法 | 见下文语境矩阵 |
| **克制** | 能少说绝不多说 | 一句话能说完绝不说两句 |
| **偶尔破例** | 极少时候多说一句，显得珍贵 | 连续加班→"早点回家" |

### 2.2 语境感知矩阵

同一个提醒，根据上下文给出不同文案：

#### 雨天提醒

| 语境 | 文案 | 为什么不同 |
|------|------|-----------|
| 工作日早 | 下午有雨，带伞出门 | 中性，实用 |
| 周末早 | 下雨了，适合窝在家 | 轻松，不制造焦虑 |
| 周末晚（已下班）| 外面下雨了，注意安全 | 关怀，不指令 |
| 连续第3天下雨 | 又是雨天，记得带伞（加点无奈的幽默） | 承认现实，共鸣 |
| 暴雨预警 | ⚠️ 暴雨预警，尽量别出门 | 紧急，不加废话 |

#### 天气降温

| 语境 | 文案 |
|------|------|
| 工作日 | 明天降温5度，加件外套 |
| 周五 | 明天降温，周末穿暖点 |
| 用户刚感冒过（如有 Health 数据）| 最近身体恢复期，注意保暖 |

#### 每日问候

| 语境 | 文案 |
|------|------|
| 周一早上 | 新的一周开始了 |
| 周三下午 | 一周过半了 |
| 周五下午 | 周末愉快 |
| 连续加班第3天 | 今天能早点下班吗？ |
| 节前一天 | 明天放假了 |
| 放假最后一天 | 明天要上班了，早点睡 |

#### 节假日

| 语境 | 文案 |
|------|------|
| 春节 | 新年好 |
| 中秋 | 中秋快乐 |
| 情人节（无伴侣标签）| 今天情人节，对自己好点 |
| 情人节（有伴侣标签）| 今天情人节 |
| 生日 | 今天是你生日，生日快乐 🎂 |

### 2.3 文案温度等级

所有文案按温度分级，推送时根据场景选择合适等级：

| 等级 | 适用场景 | 特征 | 频率占比 |
|------|---------|------|---------|
| **冷（事实）** | 紧急天气、药品、财务 | 只说事，不带感情 | 20% |
| **温（实用）** | 天气、日程、通勤 | 结论+轻微建议 | 60% |
| **暖（关怀）** | 问候、节日、加班关怀 | 带一点人情味 | 15% |
| **烫（破例）** | 用户生日、成就里程碑 | 多说一句，但不超过两句 | 5% |

**示例对照：**

同一场景不同温度：
- 冷：22°C，多云，降水概率85%
- 温：下午有雨，带伞出门
- 暖：外面要下雨了，记得带伞
- 烫：（用户生日当天）生日快乐！今天有雨，别淋着了 🎂

## 三、提醒流的温度细节

### 3.1 卡片不动的部分

极简的提醒流卡片保持不变：

```
🌧️  08:15
下午有雨，带伞出门
                    ✅
```

### 3.2 偶尔出现的"小纸条" ⭐

**定义：** 不定期在提醒流中插入一条特殊的"小纸条"，不是提醒，不是通知，就是一句话。

**出现频率：** 每周 0-1 条（不是每天都有）

**设计：**

```
┌─────────────────────────────┐
│                             │
│  最近辛苦了。                │
│                             │
│                             │
└─────────────────────────────┘
```

没有图标，没有时间，没有反馈按钮。就是一句话，安静地躺在提醒流里。

**小纸条的触发逻辑：**

| 触发条件 | 内容 | 说明 |
|---------|------|------|
| 连续工作日晚23点后还亮屏（连续3天）| 最近辛苦了。 | 不说教，就一句 |
| 连续7天每天有用率 > 80% | 今年的你，比去年的你更懂照顾自己。 | 肯定用户的成长 |
| 用户首次主动打开设置页调整标签 | 你知道自己要什么，这很好。 | 不打扰式赞赏 |
| App 使用满30天 | 和你相处一个月了。 | 纪念，但不隆重 |
| App 使用满1年 | 一年了，谢谢你在用。 | 真诚，简单 |
| 连续3天有用率 < 20%（即将触发暂停）| 有些提醒可能不太适合你，我在学着调整。 | 承认不足，不甩锅 |
| 用户删了所有标签（什么都不想收）| 没关系，安静也挺好的。 | 不挽留，尊重选择 |

**小纸条规则：**

- ✅ 文案 ≤ 15 字
- ✅ 每周最多 1 条
- ✅ 不与提醒混排，单独一个卡片
- ✅ 没有图标、没有时间戳、没有反馈按钮
- ✅ 无法左滑删除（保留一天后自动消失）
- ✅ 不触发任何推送通知
- ❌ 不用 emoji
- ❌ 不重复同一条
- ❌ 不在用户情绪明显低落时发鸡汤（如频繁忽略提醒时）

## 四、反馈交互的温度回应

### 4.1 用户点 👍 后

**不做任何弹窗或动画回应。** 点了就是点了，不需要 App 再说"谢谢你的反馈"。

但偶尔（10% 概率），提醒流顶部会出现一条系统消息：

```
知道了，以后多推这类。
```

极简，不打断，1-2秒后自动消失。

### 4.2 用户点 👎 不需要 后

弹出"不需要"二级菜单（已有设计），用户选完后：

- 选"跟我没关系" → 提醒流顶部闪过"好，记住了"（0.5s消失）
- 选"以后都别推了" → 提醒流顶部闪过"好，不会再推了"
- 选"已经知道了" → 不显示任何回应（用户已经知道了，不需要再废话）

### 4.3 用户点了"已吃"/"已做"等可执行按钮

按钮文字瞬间变为 ✅，然后 0.5s 后整条提醒淡出（而不是留在列表里占位）。

**含义：这件事已经处理了，不用再留着。**

### 4.4 用户连续忽略同类提醒

不弹窗，不在设置里加红点。只是默默地降低频率。

直到有一天，该类提醒不再出现了。用户可能不会注意到，但如果注意到了，说明 AI 做对了——**最好的温度是不让人察觉。**

## 五、边缘场景的温度

### 5.1 长时间未使用（沉默召回）

| 时长 | 通知文案 | 温度策略 |
|------|---------|---------|
| 7天 | 有空回来看看 | 像朋友发微信，不是营销短信 |
| 14天 | 今天降温了，注意保暖 | 用有用信息召回，不催促 |
| 30天 | （不再推送召回通知） | 尊重用户的离开决定 |

**绝不使用：** "您已X天未使用""快来回来吧""我们想你了"——这是产品在焦虑，不是关怀。

### 5.2 连续恶劣天气

| 场景 | 文案 | 说明 |
|------|------|------|
| 连续第2天下雨 | 又是雨天 | 承认现实 |
| 连续第3天下雨 | 雨还没停 | 不再多说 |
| 连续第4天下雨 | （不推天气提醒）| 用户已经知道了，别烦 |
| 连续第5天下雨终于晴了 | 天晴了 | 只有两个字，但够了 |

### 5.3 加班场景

| 触发条件 | 文案 | 说明 |
|---------|------|------|
| 22:00后仍在日历会议中 | 早点回家 | 只有四个字 |
| 连续3天22:00后有日程 | 这周挺忙的 | 共鸣，不说教 |
| 凌晨还在亮屏 | （不推送）| 深夜不打扰就是最大的温度 |

### 5.4 节日当天

| 场景 | 文案 |
|------|------|
| 除夕夜 | 新年好 |
| 大年初一 | （不推送，让用户和家人在一起）|
| 中秋节 | 中秋快乐 |
| 平安夜 | 平安夜快乐 |
| 跨年夜 | 新的一年，照顾好自己 |

### 5.5 用户生日

全天 Live Activity 展示：

```
生日快乐 🎂
```

推送一条通知（全天只此一条）：

```
生日快乐，今天是你的日子。
```

不做更多了。一条就够了。

### 5.6 App 更新后首次打开

```
更新好了，没什么变化。
```

不说"新版修复了X个bug""新增了Y个功能"——用户不关心。如果真的有重要新功能，在首次使用时自然引导。

## 六、LLM 文案生成规则

### 6.1 文案生成 Prompt 基准

所有文案由 LLM 生成，使用以下基准 Prompt：

```
你是一个生活提醒助手。生成提醒文案时遵循以下规则：

1. 像朋友说话，不像机器人
2. 结论先行，不说废话
3. 能用一句话说完绝不用两句
4. 不用"亲爱的""请注意""温馨提示"等套话
5. 不用 emoji（除非是生日/节日场景）
6. 不用感叹号（除非是紧急天气）
7. 同一内容连续2天文案不能相同
8. 文案长度：Live Activity ≤ 15字，通知 ≤ 20字
9. 天气类只说结论（"下雨了"），不说数据（"降水概率85%"）
10. 关怀类文案一周最多出现2次
```

### 6.2 文案审核规则

LLM 生成的文案必须通过以下检查才能推送：

| 检查项 | 规则 | 不通过处理 |
|--------|------|-----------|
| 长度 | LA ≤ 15字，通知 ≤ 20字 | 截断或重新生成 |
| 去重 | 与过去3天同类文案相似度 < 50% | 重新生成 |
| 敏感词 | 不含政治/宗教/低俗/疾病 | 重新生成 |
| 情绪过载 | 不含连续2个以上感叹号 | 去掉多余感叹号 |
| 温度匹配 | 紧急场景必须用"冷"等级 | 降级处理 |
| 每日上限 | 暖/烫等级 ≤ 2条/天 | 降级为"温" |

### 6.3 文案模板库

对于高频场景，建立模板库 + LLM 变体，不每次都纯生成：

**雨天提醒（10个变体）：**
1. 下午有雨，带伞出门
2. 外面要下雨了，记得带伞
3. 带伞了吗？
4. 下午的雨可能不小
5. 今天出门带把伞
6. 雨一会儿就到
7. 天气预报说下午有雨
8. 可能会下雨
9. 今天有雨
10. 带把伞吧

**降温提醒（8个变体）：**
1. 明天降温5度，加件外套
2. 比昨天冷了
3. 明天冷，多穿点
4. 要降温了，别感冒了
5. 注意保暖
6. 明天变天了
7. 气温降了不少
8. 穿厚点

**每日问候（按星期 + 季节组合，≥ 30个变体）：**
- 周一：新的一周开始了 / 周一，冲吧 / 又是周一
- 周二：周二了 / 一周过去一天了
- 周三：一周过半了 / 周三，坚持一下
- 周四：快周末了 / 再坚持一天
- 周五：周五了 / 快下班了
- 周六：周末愉快 / 今天休息吧
- 周日：周日了 / 明天要上班了
- 冬季工作日早上：外面冷，出门穿暖和点
- 夏季工作日早上：今天挺热的
- 雨天周末：下雨了，适合窝在家

## 七、音效的温度

极简不等于无声。音效也有温度。

| 场景 | 音效 | 设计思路 |
|------|------|---------|
| 普通提醒 | 轻柔短促的"叮"（0.3s，880Hz） | 像朋友拍你肩膀 |
| 紧急天气 | 两声短"叮叮"（0.5s） | 像朋友叫你注意 |
| 可执行按钮按下 | 极轻的确认音（0.1s） | 微小回应 |
| 小纸条出现 | 无声音 | 安静地出现就好 |

**音效温度规则：**
- 不用活泼/欢快的音效（太活泼 = 喧闹）
- 不用低沉/忧郁的音效（太严肃 = 压抑）
- 用"中性偏暖"的频率（800-1000Hz）
- 音量永远低于系统媒体音量的 50%

## 八、温度的克制清单

这是一个"checklist"，每次设计新功能时对照：

- [ ] 这句话去掉后，用户会损失信息吗？→ 如果不会，去掉
- [ ] 这个 emoji 去掉后，语气还能传达吗？→ 如果能，去掉
- [ ] 这个动画能换成系统默认吗？→ 如果能，换掉
- [ ] 这个页面能合并到其他页面吗？→ 如果能，合并
- [ ] 这条推送不发的话，用户会注意到吗？→ 如果不会，不发
- [ ] 这个功能用户每天都会用到吗？→ 如果不是，降低优先级
- [ ] 小纸条这周已经发过了吗？→ 发过了，不发
