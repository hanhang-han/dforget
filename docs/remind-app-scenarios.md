## 二、场景详细设计

> 每个场景包含：触发条件、内容模板、展示形式、可执行操作、反馈策略

### 🌤️ 一、天气相关提醒

**数据源：** 天气 API（温度、降水概率、风力、AQI、UV、湿度、预报）
**依赖权限：** 无（纯后端调用）
**类别权重默认值：** 0.70

#### 1.1 雨天带伞

| 属性 | 说明 |
|------|------|
| 触发条件 | 当日降水概率 > 60% 或未来 1h 有降雨预报 |
| 优先级 | 高（影响出行） |
| 推送时段 | 07:00-09:00（出门前） |
| 内容模板 | "今天{时段}有{强度}雨，出门记得带伞 ☂️" |
| 内容变量 | 时段=上午/下午/晚上，强度=小雨/中雨/大雨 |
| 展示形式 | Live Activity（锁屏全天展示）+ 通知 |
| 可执行操作 | [已带伞] [设置提醒14:00再查天气] |
| 反馈策略 | 高灵敏度；用户点"已带伞"→ +0.5；忽略→ 次日同类降权 |
| 冷启动 | 首日即推（确定性高，无需用户画像） |

#### 1.2 气温骤降

| 属性 | 说明 |
|------|------|
| 触发条件 | 较昨日最高温降温 ≥ 5°C |
| 优先级 | 高 |
| 推送时段 | 前一天 20:00 或当天 07:00 |
| 内容模板 | "明天降温{X}°C，最高{Y}°C最低{Z}°C，记得加件外套 🧥" |
| 展示形式 | 通知 |
| 可执行操作 | [知道了] |
| 反馈策略 | 中灵敏度；主要收集隐性行为（是否点击查看详情） |

#### 1.3 高温预警

| 属性 | 说明 |
|------|------|
| 触发条件 | 最高温 ≥ 35°C |
| 优先级 | 高（健康安全） |
| 推送时段 | 07:00（预防性）+ 14:00（二次提醒） |
| 内容模板 | "今天高温{X}°C，注意防暑，减少户外，多喝水 🥵" |
| 展示形式 | Live Activity + 通知 |
| 可执行操作 | [已注意] [查看未来3天天气] |
| 反馈策略 | 高灵敏度；二次提醒根据首次反馈决定是否推送 |

#### 1.4 低温提醒

| 属性 | 说明 |
|------|------|
| 触发条件 | 最低温 ≤ 0°C 或体感温度 ≤ -5°C |
| 优先级 | 高 |
| 推送时段 | 前一天 20:00 或当天 07:00 |
| 内容模板 | "明天气温降至{X}°C，注意保暖{附加：路面可能结冰/水管防冻} 🧊" |
| 展示形式 | 通知 |
| 可执行操作 | [知道了] |

#### 1.5 空气质量

| 属性 | 说明 |
|------|------|
| 触发条件 | AQI > 150（轻度污染以上） |
| 优先级 | 中-高 |
| 推送时段 | 07:00 |
| 内容模板 | "今天空气质量{等级}（AQI {X}），建议{建议内容} 🏠" |
| 内容变量 | 等级=轻度污染/中度污染/重度污染/严重污染 |
| 建议内容 | 减少户外活动/佩戴N95口罩/关闭门窗/开启净化器 |
| 展示形式 | Live Activity（AQI高时全天展示） |
| 反馈策略 | 低灵敏度（空气质量是事实信息，用户不太会反馈） |

#### 1.6 紫外线

| 属性 | 说明 |
|------|------|
| 触发条件 | UV 指数 ≥ 6（夏季晴天常见） |
| 优先级 | 低 |
| 推送时段 | 09:00（出门前） |
| 内容模板 | "今天紫外线{等级}，外出注意防晒 🧴" |
| 内容变量 | 等级=很强/极强 |
| 展示形式 | Live Activity（整合到天气卡片中） |

#### 1.7 大风/沙尘/暴雪/暴雨

| 属性 | 说明 |
|------|------|
| 触发条件 | 对应气象预警信号 |
| 优先级 | 紧急 |
| 推送时段 | 实时（收到预警后立即推送，不受频率限制） |
| 内容模板 | "{类型}预警！{防护建议} ⚡" |
| 展示形式 | 紧急通知（iOS Critical Alert，静音模式也能响） |
| 注意 | 需要用户在设置中授权"紧急通知"权限 |

#### 1.8 穿衣建议

| 属性 | 说明 |
|------|------|
| 触发条件 | 每日 07:00 固定触发 |
| 优先级 | 低 |
| 推送时段 | 07:00 |
| 内容模板 | "今天{X}-{Y}°C，{穿衣建议}" |
| 内容变量示例 | "15-22°C，短袖+薄外套" / "5-10°C，毛衣+外套" / "25-30°C，短袖短裤" |
| 展示形式 | Live Activity（整合到天气卡片，作为"今日天气"的一部分） |
| 特殊逻辑 | 穿衣建议基于体感温度而非纯气温，考虑风寒/湿度 |

#### 1.9 回南天/梅雨季

| 属性 | 说明 |
|------|------|
| 触发条件 | 湿度 > 85% + 气温回升（春季典型） |
| 优先级 | 中 |
| 推送时段 | 07:00 |
| 内容模板 | "回南天来啦！关好门窗，洗好的衣服用烘干 💧" |
| 展示形式 | 通知 |
| 地域限制 | 仅华南地区（广东、广西、福建、海南等） |

### 🕐 二、时间作息提醒

**数据源：** 系统时间
**依赖权限：** 无
**类别权重默认值：** 0.50

#### 2.1 每日问候

| 属性 | 说明 |
|------|------|
| 触发条件 | 用户设定的起床时间（默认 08:00） |
| 优先级 | 低 |
| 内容模板（工作日）| "早上好！今天{星期}，离周末还有{X}天 ☀️" |
| 内容模板（周末）| "周末愉快！今天没有安排的话就好好休息 ☕" |
| 内容模板（节日）| "{节日名}快乐！🎉 祝你{祝福语}" |
| 展示形式 | Live Activity（作为"今日概览"的一部分） |
| 特殊逻辑 | 文案由 LLM 根据日期、节日、天气组合生成，避免重复 |

#### 2.2 出门检查

| 属性 | 说明 |
|------|------|
| 触发条件 | 起床时间 + 30min 后 |
| 优先级 | 中 |
| 内容模板 | "出门前检查：手机、钥匙、钱包、耳机" |
| 变量逻辑 | 雨天→追加"雨伞"；冬季→追加"手套"；有航班→追加"身份证" |
| 展示形式 | Live Activity |
| 可执行操作 | [已检查] |
| 反馈策略 | 中灵敏度；用户如果连续3天忽略，降低频率至每周2-3次 |

#### 2.3 饮水提醒

| 属性 | 说明 |
|------|------|
| 触发条件 | 每 2 小时（可配置间隔） |
| 优先级 | 低 |
| 推送时段 | 08:00-21:00（夜间不推） |
| 内容模板 | "已经{X}小时没喝水了，喝一杯吧 💧" |
| 展示形式 | 通知（低优先级，静默推送） |
| 可执行操作 | [已喝] [30分钟后提醒] |
| 反馈策略 | 低灵敏度；频繁忽略→降低频率至每3-4小时 |
| 特殊逻辑 | 高温天自动缩短间隔至1.5小时 |

#### 2.4 午休提醒

| 属性 | 说明 |
|------|------|
| 触发条件 | 工作日 13:00 |
| 优先级 | 低 |
| 内容模板 | "该午休了，闭眼15分钟下午效率更高 😴" |
| 展示形式 | 通知 |
| 反馈策略 | 低灵敏度；工作相关提醒容易被忽略，不主动降权 |

#### 2.5 下午提神

| 属性 | 说明 |
|------|------|
| 触发条件 | 工作日 15:00 |
| 优先级 | 低 |
| 内容模板 | "下午犯困？站起来走走，喝杯水 💪" |
| 展示形式 | 通知 |
| 反馈策略 | 低灵敏度 |
| 特殊逻辑 | 每次文案不同（走路/拉伸/深呼吸/吃水果/聊天/看窗外），由 LLM 生成 |

#### 2.6 睡眠引导

| 属性 | 说明 |
|------|------|
| 触发条件 | 用户设定的睡觉时间 - 30min / - 1h |
| 优先级 | 中 |
| 内容模板 | "该准备洗漱了，早点休息 💤" |
| 展示形式 | 通知 |
| 变量逻辑 | 连续3天晚睡→文案变为"最近都在熬夜，今晚试试11点前睡？" |
| 反馈策略 | 中灵敏度 |

#### 2.7 熬夜警告

| 属性 | 说明 |
|------|------|
| 触发条件 | 00:00 后手机仍亮屏（通过 App 前台检测） |
| 优先级 | 低（不打扰原则） |
| 推送限制 | 仅在工作日前一天推送（周末/假期不打扰） |
| 内容模板 | "{幽默文案}" |
| 文案示例 | "都凌晨{X}点了，明天{Y}（周一/有早会），确定不睡？" |
| 展示形式 | 通知（静默，不震动） |
| 反馈策略 | 不收集反馈（用户已经很困了，不要制造负担） |

### 📅 三、日历事件相关

**数据源：** 系统日历（EventKit）
**依赖权限：** 日历读写权限（低）
**类别权重默认值：** 0.60

#### 3.1 会议提醒

| 属性 | 说明 |
|------|------|
| 触发条件 | 日历中有会议事件，提前 15min 触发 |
| 优先级 | 高 |
| 内容模板 | "{X}分钟后「{会议名}」即将开始" |
| 变量逻辑 | 参会人数>5→标记"重要会议"；有线上链接→追加"点击加入会议" |
| 展示形式 | Live Activity（倒计时）+ 通知 |
| 可执行操作 | [加入会议]（如果有线上链接）/ [查看详情] |
| 反馈策略 | 高灵敏度；会议相关性用户感知最强 |

#### 3.2 重要事件前准备

| 属性 | 说明 |
|------|------|
| 触发条件 | 日历事件包含关键词（出差/航班/面试/考试/汇报）提前1天 |
| 优先级 | 高 |
| 内容模板 | "明天要{事件类型}，记得检查：{检查清单}" |
| 关键词清单 | 出差→"身份证、充电器、洗漱包"；面试→"简历、作品集、路线"；航班→"登机牌、身份证、充电宝" |
| 展示形式 | 通知 |
| 可执行操作 | [已准备好] [添加更多清单项] |
| 反馈策略 | 高灵敏度 |

#### 3.3 生日/纪念日

| 属性 | 说明 |
|------|------|
| 触发条件 | 日历中有生日事件当天 / 纪念日前 7 天 |
| 优先级 | 中 |
| 内容模板（生日）| "今天是{名字}的生日，记得送个祝福 🎂" |
| 内容模板（纪念日）| "下周{X}是{事件名}，该准备一下了 🎁" |
| 展示形式 | 通知 |
| 反馈策略 | 中灵敏度 |

#### 3.4 日程密度提醒

| 属性 | 说明 |
|------|------|
| 触发条件 | 当天 ≥ 5 个事件 → "紧凑"；= 0 个事件 → "空闲" |
| 优先级 | 低 |
| 内容模板（紧凑）| "今天有{X}个日程安排，注意时间管理 📋" |
| 内容模板（空闲）| "今天没有安排，好好放松！" |
| 展示形式 | Live Activity（作为"今日概览"一部分） |
| 反馈策略 | 低灵敏度 |

### 🍎 五、饮食健康

**数据源：** Apple Health + 时间
**依赖权限：** HealthKit（中）
**类别权重默认值：** 0.30
**上线版本：** V1.1

| 场景 | 触发条件 | 内容示例 | 可执行操作 | 反馈注意 |
|------|---------|---------|-----------|---------|
| 三餐提醒 | 固定时段（早8/午12/晚18） | "到饭点了，该吃饭了 🍱" | [已吃] [设餐后提醒] | 低灵敏度，饮食提醒容易被忽略但不代表不需要 |
| 饮水目标 | Health 饮水数据 + 每2h | "今天已喝4杯，再喝2杯达标 💧" | [记一杯] [查看今日饮水] | 中灵敏度 |
| 减少外卖 | 连续5天推断外卖（可通过App使用时间推断外卖App打开频率） | "这周吃了5次外卖了，自己做顿饭吧 🥗" | 无 | 低灵敏度 |
| 补充维D | 冬季/连续阴雨天 + UV<2 | "最近日照不足，注意补充维生素D ☀️" | 无 | 低灵敏度 |
| 睡前禁食 | 22:00 后 | "睡前吃东西容易积食，忍忍吧 😅" | [已忍住] | 低灵敏度 |

### 🏋️ 六、运动健身

**数据源：** Apple Health（步数、运动记录、心率）+ 时间
**依赖权限：** HealthKit（中）
**类别权重默认值：** 0.30（⚠️ 容易被忽略，默认权重不宜过高）
**上线版本：** V1.1

| 场景 | 触发条件 | 内容示例 | 可执行操作 | 反馈注意 |
|------|---------|---------|-----------|---------|
| 久坐提醒 | Health 计步=0 持续 60min+ | "已经坐了1小时了，起来走走！🚶" | [已起身] [5分钟后再提醒] | ⚠️ 被忽略率极高（>60%），需要智能时段选择 |
| 运动目标 | Health 步数对比目标 | "今天已走6000步，再走3000步达标 🏃" | [查看详情] | 中灵敏度 |
| 连续未运动 | Health 连续3天无运动记录 | "三天没运动了，今天动一动吧 🏋️" | 无 | ⚠️ 高忽略率，需在用户选了"运动"标签后才推 |
| 天气好运动 | 傍晚 + 天气晴 + 气温15-28°C | "今天天气不错，下班后可以去跑步 🏃‍♂️" | 无 | 低灵敏度 |
| 运动后提醒 | Health 新增运动记录 | "运动完记得补水和拉伸！💧🧘" | [已补水] | 高灵敏度（时机精准） |
| 月度总结 | 每月1日 | "上个月运动{X}次，比上个月{增/减}{Y}次" | [查看详情] | 低灵敏度 |

**⚠️ 运动类特别说明：**
- 久坐提醒是"好心但容易被烦"的典型，必须结合用户行为数据智能判断推送时机
- 建议只在用户日历中标记为"工作时间"的时段推送久坐提醒
- 如果用户连续一周忽略 → 自动降频至每周2次，或暂停并提示"已暂停久坐提醒"
- 用户选了运动标签后权重提升到 0.60，否则保持 0.30

### 💼 七、工作/学习

**数据源：** 日历 + 时间 + （可选）屏幕使用时间
**依赖权限：** 低
**类别权重默认值：** 0.40
**上线版本：** V1.1

## 三、展示形式设计

### 3.1 Live Activity（锁屏常驻）— 核心展示形态

**设计原则：** 一个 Live Activity 同时只展示最重要的1条信息，内容必须精简。

**标准布局：**

```
┌─────────────────────────────────────┐
│  🔔 智能提醒                        │
│                                     │
│  🌧️ 22°C 多云                       │
│  下午有雨，带伞出门                  │
│                                     │
│  [换一个]  [👍]  [✕]                │
└─────────────────────────────────────┘
```

**不同内容类型的布局变体：**

```
天气型：
┌─────────────────────────────────────┐
│  🌧️ 22°C  多云  |  下午有雨          │
│  带伞出门 · 短袖+薄外套              │
└─────────────────────────────────────┘

倒计时型：
┌─────────────────────────────────────┐
│  📋 产品评审会议                      │
│  ⏱ 还有 15 分钟                     │
└─────────────────────────────────────┘

进度型：
┌─────────────────────────────────────┐
│  💧 今日饮水   4/8 杯                │
│  ████████░░░░░░░░░░░░  50%         │
└─────────────────────────────────────┘

问候型：
┌─────────────────────────────────────┐
│  ☀️ 早上好！                         │
│  周三 · 22°C · 今天有2个会议         │
└─────────────────────────────────────┘
```

**Live Activity 内容编排优先级：**
1. 紧急/安全类（暴雨、高温、药品）→ 强制展示
2. 即将发生的日历事件（会议倒计时）
3. 天气概况
4. 其他高权重类别

### 3.2 通知推送

**标准通知布局：**

```
┌─────────────────────────────────────┐
│  🔔 智能提醒                        │
│                                     │
│  🌧️ 今天下午有雨，出门记得带伞        │
│                                     │
│     [✓ 有用]        [✗ 不需要]       │
└─────────────────────────────────────┘
```

**可执行通知布局：**

```
┌─────────────────────────────────────┐
│  🔔 智能提醒                        │
│                                     │
│  💊 该吃降压药了                     │
│  每日 08:00                         │
│                                     │
│  [✅ 已吃]    [⏰ 30分钟后]    [跳过]  │
└─────────────────────────────────────┘
```

### 3.3 灵动岛（Dynamic Island）

适用于**短时、实时**的信息展示：

- 会议倒计时（展开显示详细信息）
- 运动进行中（步数实时更新）
- 天气预警（展开显示详细建议）

**注意：** 灵动岛和 Live Activity 共用 ActivityKit 框架，一个 App 同时只有一个活跃的 Activity。需要做好**切换逻辑**。

## 四、推送频率控制（整合反馈机制）

> 详细反馈策略见 `remind-app-feedback.md`

### 4.1 基础频率规则

| 时段 | 推送上限 | 说明 |
|------|---------|------|
| 00:00-07:00 | 0-1条 | 仅紧急预警（暴雨/高温/药品），静音推送 |
| 07:00-09:00 | 2-3条 | 早间集中（天气+日历+问候） |
| 09:00-12:00 | 1-2条 | 工作时段最小化打扰 |
| 12:00-14:00 | 1-2条 | 午休时段 |
| 14:00-18:00 | 1-2条 | 下午时段 |
| 18:00-22:00 | 2-3条 | 晚间时段 |
| 22:00-24:00 | 0-1条 | 仅睡眠引导，静音 |

### 4.2 动态频率调整

| 用户行为 | 调整 |
|---------|------|
| 当天有用率 > 70% | 次日可适当增加推送（+1条） |
| 当天有用率 < 30% | 次日减少推送（-2条） |
| 连续3天关闭率 > 50% | 暂停推送48h |
| 单类提醒连续7天被忽略 | 该类自动暂停，推送一条"已暂停XX提醒" |
| 用户主动降低每日上限 | 立即生效，7天后可提示"是否恢复" |

### 4.3 全局控制

- **每日通知上限：** 默认 8 条，用户可调整 3-15 条
- **同类间隔：** ≥ 30 分钟
- **紧急通知豁免：** 暴雨/高温/地震等不受频率限制（但需用户授权紧急通知）
- **免打扰时段：** 用户可设定自定义免打扰时段，默认 22:00-07:00
- **日历联动免打扰：** 检测到日历中标记为"会议"的事件时，自动免打扰（可关闭）

## 五、AI 决策引擎

### 5.1 推送决策完整流程

```
┌──────────────────────┐
│  触发源               │
│  ├─ 定时调度（每5min） │
│  ├─ 天气事件（实时）   │
│  ├─ 日历变更（实时）   │
│  └─ Health 更新（实时）│
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  上下文采集            │
│  ├─ 时间 + 星期 + 节日 │
│  ├─ 天气（实时+预报）  │
│  ├─ 日历事件           │
│  ├─ Health 数据        │
│  └─ 用户偏好模型       │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  候选提醒生成          │
│  遍历所有场景规则       │
│  输出：满足条件的提醒   │
│  候选列表              │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  偏好过滤             │
│  ├─ 权重 < 0.10 → 排除│
│  ├─ 暂停中的类别 → 排除│
│  └─ 用户未选标签 → 排除│
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  频率控制             │
│  ├─ 今日已推数量检查   │
│  ├─ 时段上限检查       │
│  ├─ 同类间隔检查       │
│  └─ 免打扰时段检查     │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  智能排序              │
│  Score = 匹配度        │
│        × 偏好权重      │
│        × 时效性       │
│        × 多样性系数    │
│  (详见反馈文档3.4节)   │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  文案个性化            │
│  LLM 根据以下生成文案   │
│  ├─ 场景模板           │
│  ├─ 用户画像           │
│  ├─ 天气/时间上下文    │
│  └─ 历史文案去重       │
│  (避免连续2天相同文案)  │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  输出                 │
│  ├─ Live Activity ×1  │
│  ├─ 通知推送 × 1-2    │
│  └─ 待推送队列（排队）  │
└──────────────────────┘
```

### 5.2 文案生成策略

**核心原则：**
1. **绝不重复：** 连续2天的同类提醒文案不能相同
2. **结合上下文：** 同一个"带伞"提醒，结合温度、工作日/周末、用户是否即将出门生成不同文案
3. **自然不做作：** 不用"温馨提示""亲爱的用户"等营销语言
4. **简洁：** 通知文案 ≤ 30字，Live Activity 文案 ≤ 20字
5. **有温度：** 偶尔用幽默/拟人化语气，但不刻意

**文案质量保障：**
- 建立文案模板库（每类场景 ≥ 10 个变体）
- LLM 生成时以模板为基准，注入上下文变量
- 敏感场景（药品、财务）使用固定模板，不使用 LLM 自由生成
- 上线前人工审核所有模板

## 六、隐私与安全设计

| 数据类型 | 存储位置 | 传输方式 | 保留策略 |
|---------|---------|---------|---------|
| 日历数据 | 本地 + 端到端加密云端 | TLS 1.3 | 用户删除 App 立即清除 |
| Health 数据 | 仅本地（不上传） | — | 本地存储 |
| 天气数据 | 服务端缓存 | — | 24h 自动清除 |
| 用户偏好/反馈 | 端到端加密云端 | TLS 1.3 | 同上 |
| 财务信息 | 仅本地 | — | 用户删除 App 立即清除 |
| 位置数据（V2+） | 仅本地 | — | 本地存储，30天自动清除 |

**核心原则：**
- Health 数据**永不上传**到服务器，所有 Health 相关推理在设备端完成
- 财务信息仅存本地，通知中不显示敏感详情
- 用户可一键导出/删除所有个人数据
- 不向第三方分享任何用户数据
