# 智能提醒 App — 用户引导机制设计文档

> 版本：v1.0 | 2026-05-06
> 目标：让用户在 2 分钟内感受到价值，5 分钟内完成核心设置，零认知负担

---

## 一、设计原则

1. **先体验，后设置** — 不做传统"欢迎页→注册→填表→进入"的流程，让用户先看到效果
2. **每次只问一件事** — 任何一步都只有一个选择或输入，绝不同时问两个问题
3. **可跳过但不丢功能** — 所有设置都可以跳过，之后在 App 内随时调整
4. **即时反馈** — 用户每做一个选择，立刻看到效果（"你选了天气→锁屏已经帮你显示天气了"）
5. **2 分钟感知价值** — 从下载到看到第一条 Live Activity，不超过 2 分钟

---

## 二、引导流程总览

```
下载安装
    ↓
[Step 1] 启动动画 + 品牌印象 (3秒)
    ↓
[Step 2] 通知权限申请 (即刻)
    ↓
[Step 3] 即时体验 — 看到第一条 Live Activity (10秒)
    ↓
[Step 4] 日历权限申请 (推荐)
    ↓
[Step 5] 兴趣标签选择 (可跳过)
    ↓
[Step 6] 推送偏好微调 (可跳过)
    ↓
[Step 7] 进入 App 主页 + 引导弹窗
    ↓
后台：冷启动观察期（Day 1-3）
    ↓
[Step 8] 深度引导 — 首次正反馈后弹出 (Day 1-3)
    ↓
[Step 9] 进阶功能引导 — Health权限/更多标签 (Day 4-7)
```

## 三、分步详细设计

### Step 1：启动动画（3秒）

**目标：** 建立品牌印象，不是"又一个工具"

```
┌─────────────────────────────────────┐
│                                     │
│            (App Logo 动画)           │
│                                     │
│         你的生活，我来提醒            │
│                                     │
│                                     │
│                                     │
│              [开始体验 →]            │
│                                     │
└─────────────────────────────────────┘
```

**设计要点：**
- 动画 ≤ 3 秒，不能长（用户会烦躁）
- 如果 App 是被通知打开的（比如更新后首次打开），跳过此步骤
- 底部小字："无需注册，立即使用"

---

### Step 2：通知权限申请

**目标：** 尽早获取通知权限（这是 App 的生命线）

**时机：** 用户点击"开始体验"后，**立即弹出**

```
┌─────────────────────────────────────┐
│                                     │
│   🔔 通知是核心功能                  │
│                                     │
│   我会通过通知和锁屏卡片              │
│   给你推送生活提醒                   │
│                                     │
│   你可以随时关闭，或调整频率          │
│                                     │
│       [允许通知]     [稍后再说]       │
│                                     │
│                                     │
└─────────────────────────────────────┘
```

**关键设计：**

| 策略 | 说明 |
|------|------|
| 解释"为什么需要" | 告诉用户通知是用来干什么的，不是空弹权限 |
| 给出"稍后"选项 | 如果用户拒绝，**不要立刻再弹**，等到 Step 7 结束后再温和引导一次 |
| 拒绝后的降级方案 | 用户拒绝通知→仍可使用 App 查看天气/日历等，但体验打折扣，首页显示提示条 |

**拒绝通知后的引导（Step 7 结束时）：**

```
┌─────────────────────────────────────┐
│  💡 开启通知才能收到提醒哦           │
│  点击这里前往设置 →                   │
│  [关闭 ×]                           │
└─────────────────────────────────────┘
```

- 每天最多提示 1 次，连续 3 天拒绝后永久不再提示
- 永久不再提示后，在设置页保留手动开启入口

---

### Step 3：即时体验 — 看到第一条 Live Activity

**目标：** 让用户立刻看到产品价值，这是**最关键的一步**

**时机：** 通知权限授予后，立即触发

```
手机锁屏自动展示：

┌─────────────────────────────────────┐
│  ☀️ 早上好！                         │
│  今天周三 · 22°C 多云 · 带伞出门     │
│                                     │
│  [换一个]  [👍]  [✕]                │
└─────────────────────────────────────┘
```

**同时 App 内展示引导：**

```
┌─────────────────────────────────────┐
│                                     │
│   ✅ 已为你的锁屏添加了天气卡片       │
│                                     │
│   亮屏看看 →                         │
│                                     │
│   ↑ 这是"灵动提醒"——               │
│   不用打开 App 就能看到              │
│                                     │
│         [接下来 →]                   │
│                                     │
└─────────────────────────────────────┘
```

**为什么这一步这么重要：**
- 用户刚给了一个权限（通知），需要**立刻得到回报**
- Live Activity 在锁屏上是一个"惊喜时刻"——大多数用户没见过锁屏常驻信息
- 这一步创造了"啊，这个 App 真的不一样"的瞬间

**如果用户拒绝了通知权限：**
- 仍然展示这个引导页，但文案改为"锁屏通知需要在设置中开启，我们先看看其他功能"
- 引导用户进入 App 主页，首页仍可看到天气信息（App 内展示）

---

### Step 4：日历权限申请

**目标：** 获取日历权限，让提醒更个性化

**时机：** Step 3 之后

```
┌─────────────────────────────────────┐
│                                     │
│   📅 读取日历，提醒更懂你            │
│                                     │
│   允许读取日历后，我可以：           │
│   · 会议前15分钟提醒你              │
│   · 出差前帮你列清单                │
│   · 纪念日/生日提前通知             │
│                                     │
│    [允许日历]    [暂时不用]          │
│                                     │
│    🔒 你的日历数据不会被上传         │
│                                     │
└─────────────────────────────────────┘
```

**关键设计：**
- 明确列出**3个具体好处**（不是泛泛的"更好的体验"）
- 底部强调隐私（日历数据不上传）
- 如果用户允许 → 立刻读取近期日历，显示"发现了 X 个即将到来的事件"

**允许后的即时反馈：**

```
┌─────────────────────────────────────┐
│                                     │
│   📅 发现了你的近期日程              │
│                                     │
│   · 明天 10:00 产品评审会议          │
│   · 后天 14:00 和张总吃饭           │
│   · 周五 09:00 英语课               │
│                                     │
│   我会在合适的时候提醒你 ✨           │
│                                     │
│         [接下来 →]                   │
│                                     │
└─────────────────────────────────────┘
```

- 如果用户近期没有日历事件 → 显示"暂无近期日程，有新日程时我会自动提醒你"
- **绝不让这一步看起来空**，即使没有数据也要给出正向反馈

**目标：** 初步了解用户偏好，控制推送范围

**时机：** Step 4 之后

```

│                                     │
│   🎯 选择你关心的提醒类型            │
│                                     │
│   （随时可以调整，全部跳过也可以）     │
│                                     │
│   ┌──────┐  ┌──────┐  ┌──────┐     │

│   │ 天气  │  │ 健康  │  │ 工作  │     │
│   │ ✅   │  │      │  │ ✅   │     │
│   └──────┘  └──────┘  └──────┘     │
│   ┌──────┐  ┌──────┐  ┌──────┐     │
│   │ 🏠  │  │ 💰  │  │ 📖  │     │
│   │ 生活  │  │ 财务  │  │ 成长  │     │
│   │ ✅   │  │      │  │      │     │
│   └──────┘  └──────┘  └──────┘     │
│   ┌──────┐  ┌──────┐  ┌──────┐     │
│   │ 👨‍👩‍👧  │  │ 🐱  │  │ 🧘  │     │
│   │ 家庭  │  │ 宠物  │  │ 情绪  │     │
│   │      │  │      │  │      │     │
│   └──────┘  └──────┘  └──────┘     │
│                                     │
│    [跳过，全部开启]     [开始使用 →]  │
│                                     │
└─────────────────────────────────────┘
```

**关键设计：**

| 策略 | 说明 |
|------|------|
| 预选推荐 | 天气+生活默认预选（基于最通用的需求） |
| 零标签也可以 | 点"跳过"= 全部开启，后续通过反馈机制自动筛选 |
| 不要求必选 | 不做"至少选3个"的限制 |
| 一句话说明 | 每个标签下方可显示一句说明（展开后），默认不显示避免视觉负担 |
| 二级子标签（可选） | 选中"天气"后，可展开选择子类：日常天气/极端天气预警/穿衣建议/空气质量 |

**选中后的即时反馈：**

```
用户选了「天气」→ 卡片放大 + 弹出气泡 "☀️ 已开启天气提醒"
用户选了「财务」→ 弹出气泡 "💳 稍后可设置还款日"
用户取消选择 → 无动画（静默，不打扰）
```

### Step 8：深度引导 — 首次正反馈后

**目标：** 在用户已经感受到价值后，引导更深度个性化

**触发时机：** 用户首次点击"👍 有用"按钮后

```
┌─────────────────────────────────────┐
│                                     │
│   🎉 你觉得这条提醒有用！            │
│                                     │
│   想让提醒更懂你吗？                 │
│                                     │
│   我可以了解更多关于你的信息：        │
│                                     │
│   ┌──────────────────────────┐     │
│   │ 🐱 你有宠物吗？           │     │
│   └──────────────────────────┘     │
│   ┌──────────────────────────┐     │
│   │ 👨‍👩‍👧 你的家庭情况？         │     │
│   └──────────────────────────┘     │
│   ┌──────────────────────────┐     │
│   │ 💰 需要财务提醒吗？       │     │

│                                     │

```

**为什么放在这里而不是首次启动：**
- 此时用户已经给过正反馈，说明认可产品价值
- 心理状态是"这个不错，我可以多给点信息"
- 不会产生"还没用就要我填信息"的抵触感

│   │  (输入框)                 │     │

- 用户可以随时跳过，跳过后在设置中仍可配置

### Step 9：进阶功能引导（Day 4-7）

**目标：** 引导用户开启 Apple Health 等高级权限

**触发时机：** 用户使用 4-7 天后，且有用率 > 40%

```
┌─────────────────────────────────────┐
│                                     │
│   💪 升级你的提醒                    │
│                                     │
│   开启健康数据后，我可以：           │
│   · 久坐了提醒你站起来              │
│   · 追踪你的饮水目标                │
│   · 运动后提醒你拉伸补水            │
│                                     │
│   🔒 健康数据仅存在你的手机上        │
│                                     │
│    [开启健康数据]    [暂时不用]       │
│                                     │
└─────────────────────────────────────┘
```

**为什么放在 Day 4-7：**
- 用户已使用多天，有了一定信任基础
- 有用率 > 40% 说明用户认可推送质量
- 健康权限较敏感，需要更高信任度
- 如果有用率 < 40%，不弹出（说明产品还没证明价值，此时要权限会被拒绝）

## 五、召回引导（用户沉默后）

### 5.1 7天未打开 App

```
推送通知：

"好久不见 👋 你错过了这些提醒：
· 周二暴雨预警（你没看到）
· 周三母亲节提醒

回来看看吧 →"
```

- 不是恐吓式（"你可能会错过重要提醒！"），是温和式
- 展示用户实际可能关心的内容

### 5.2 14天未打开 App

```
推送通知：

"最近天气变化大，回来看看今天的提醒？☀️"
```

- 极简，不啰嗦

### 5.3 30天未打开 App

- 不再推送召回通知
- 如果用户重新打开 App → 进入"重新引导"流程（轻量版，只重新确认权限和标签）

## 六、功能发现引导

对于 App 内的次要功能，使用"场景触发式引导"而非主动推送：

| 功能 | 触发条件 | 引导方式 |
|------|---------|---------|
| 提醒历史 | 用户在首页向下滑动 | 自动加载历史列表 + 首次显示气泡"在这里查看所有提醒记录" |
| AI 洞察 | 用户首次打开"提醒历史"页 | 底部显示 AI 洞察卡片 + "这是 AI 根据你的反馈生成的" |
| 设置页 | 用户首次点击 ⚙️ | 标签页中高亮"推送时段"和"免打扰" |
| 月度报告 | 每月1日 | 通知推送月报摘要 + 引导点击查看详情 |
| 自定义提醒 | 用户连续3次点"不需要"同类提醒 | 弹出"是否要自定义这类提醒的规则？"引导进入规则设置 |
| 深色模式 | 用户在系统切换到深色模式后首次打开 App | 首页顶部气泡"已自动切换深色模式 🌙" |

## 八、特殊场景处理

### 8.1 老年用户

- 引导文字更大（使用 Dynamic Type）
- Step 5 标签选择使用更大的卡片
- 默认推送上限设为 3 条（减少打扰）
- 重点引导"药品提醒"和"天气提醒"

### 8.2 被通知唤醒（非主动打开）

- 如果用户是点击通知打开 App → 跳过 Step 1-3，直接显示通知相关内容
- 如果用户是更新后首次打开 → 跳过 Step 1，但重新检查权限状态

### 8.3 用户中途退出引导

- 记录用户退出的步骤
- 下次打开 App → 从退出步骤继续（不从头开始）
- 如果用户在 Step 2（通知权限）退出 → 下次打开直接跳到权限申请页
- 如果用户在 Step 5（标签选择）退出 → 下次打开直接进入主页，首页显示"完成设置"提示

### 8.4 系统权限被撤销

```
通知权限被关闭 → App 内顶部显示横幅：
"通知已被关闭，提醒功能无法使用 [前往设置]"

日历权限被关闭 → App 内提示：
"日历权限被关闭，会议提醒等功能受影响 [前往设置]"
```

## 十、与反馈机制的衔接

| 引导步骤 | 产生的反馈数据 | 对偏好模型的影响 |
|---------|--------------|----------------|
| Step 5 兴趣标签选择 | 显性反馈，高权重 | 选中类别权重 → 0.75，未选 → 0.05 |
| Step 6 推送偏好设置 | 显性反馈，最高权重 | 直接写入用户配置 |
| Step 3 Live Activity 交互 | 隐性反馈 | 根据换一个/关闭行为初始化天气权重 |
| Step 4 日历权限 | 间接反馈 | 允许→日历类别权重+0.2 |
| Step 8 深度引导选择 | 显性反馈 | 新增类别权重初始化为 0.60 |
| Step 9 Health 权限 | 间接反馈 | 允许→运动/饮食类别权重+0.2 |
