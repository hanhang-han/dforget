## 1. 产品概述

### 1.1 产品定义

一款 iOS 原生智能提醒 App，核心形态为灵动岛（Live Activity）长居锁屏。AI 基于用户上下文——天气、日历、时间、Health 健康数据等——自动生成生活提醒，无需用户手动输入。

### 1.2 核心价值主张

> **"你不主动找提醒，提醒主动找到你。"**

| 维度 | 说明 |
|------|------|
| 零输入 | AI 自动推断用户需求，无需设置提醒规则 |
| 上下文感知 | 天气、日历、健康数据等多维度信息融合 |
| 锁屏原生 | 灵动岛长驻，不打扰但始终可见 |
| 有温度 | 极简设计，文案有人情味，不机械 |

### 1.3 产品路线图

- **V1.0（上线）：** 天气 + 时间 + 日历驱动提醒，免费
- **V1.1（+2 月）：** 新增 Health（运动/睡眠）、饮食、工作、生活服务、节日提醒
- **V2.0（+6 月）：** 心理关怀、家庭、宠物、个人成长、财务提醒
- **反馈机制：** 隐性行为追踪 + 显性微交互（点赞/不感兴趣）+ 主动设置 + AI 对话

## 2. 市场分析

### 2.1 目标用户画像

#### 主要用户群

**群组 A：城市白领（25-35 岁）**
- 职业：互联网、金融、咨询、教培等行业从业者
- 痛点：工作节奏快，生活细节常被忽略（忘带伞、忘喝水、久坐不动）
- 使用场景：通勤、办公、出差
- 设备：iPhone 14 Pro 及以上（灵动岛机型），iOS 17+
- 付费意愿：中等偏高，习惯为效率工具付费

**群组 B：大学生 / 年轻职场人（18-24 岁）**
- 痛点：时间管理能力弱，依赖手机但记性差
- 使用场景：上课、自习、社交、兼职
- 付费意愿：较低，但愿意为"好看+好用"买单
- 特点：社交传播意愿强，是小红书/抖音的活跃用户

**群组 C：健康关注者（30-45 岁）**
- 痛点：想养成健康习惯但坚持不下来
- 使用场景：运动提醒、喝水提醒、睡眠提醒
- 付费意愿：高，对健康相关功能愿意花钱

#### 用户痛点地图

| 痛点 | 严重度 | 现有方案 | 我们的方案 |
|------|--------|----------|------------|
| 忘带伞/忘穿外套 | ⭐⭐⭐⭐ | 天气 App 需主动看 | 自动推送"今天可能下雨，带伞出门" |
| 坐太久不动 | ⭐⭐⭐⭐ | 手表/手环提醒 | 基于日历+久坐检测自动提醒 |
| 忘喝水 | ⭐⭐⭐ | 需手动设定闹钟 | 基于天气/运动/时间智能提醒 |
| 忘重要日程 | ⭐⭐⭐ | 日历提醒太冷冰冰 | 带温度的提前提醒"明天有面试，早点睡" |
| 生活缺乏仪式感 | ⭐⭐⭐ | 无 | 节日、纪念日、季节更替提醒 |

- SAM（中国区）≈ **1500-2000 万潜在用户**

#### SOM（可获得市场）

- 首年目标：通过 ASO + 社交传播获取自然流量
- 保守估计首年注册用户 **3-5 万**，活跃用户 **1-2 万**

### 2.4 差异化定位

**核心差异 = "主动" + "智能" + "原生"**

```
┌─────────────────────────────────────────────────┐
│                 用户需要提醒时                     │
│                                                   │
│  传统方案：用户 → 手动设置 → 收到提醒              │
│  我们方案：AI 观察 → 自动推送 → 用户只管看          │
│                                                   │
│  关键差异：用户不需要知道"我要被提醒什么"             │
└─────────────────────────────────────────────────┘
```

| 差异维度 | 我们 vs 竞品 |
|----------|-------------|
| **输入方式** | 零输入 vs 需手动设置 |
| **提醒时机** | AI 最优时机 vs 固定时间/随机 |
| **提醒内容** | 上下文相关 vs 预设模板 |
| **展示形态** | 灵动岛原生 vs 推送通知 |
| **情感温度** | 有人味 vs 机械化 |
| **数据利用** | 多源融合 vs 单一数据源 |

**一句话定位：** "你的生活副驾驶——不需要你操作，但一直在你身边。"

## 3. 商业模式

### 3.1 盈利模式选择

**推荐：Freemium + 订阅制**

选择理由：
- 免费版降低使用门槛，利于自然增长
- 订阅制提供持续收入，支撑 LLM/API 运营成本
- 中国区用户对订阅制的接受度已在逐步提升（微信/音乐/视频教育到位）
- 一次性买断无法覆盖持续的 AI 推理成本

> 不选择纯广告模式：广告提醒会破坏"有温度"的产品调性，且灵动岛不支持广告展示。

### 3.2 免费 / Pro 功能划分

| 功能模块 | 免费版 | Pro 版 |
|----------|--------|--------|
| 基础提醒（天气+时间） | ✅ 每日 3 条 | ✅ 不限 |
| 日历联动提醒 | ✅ 基础 | ✅ 高级（多日历、智能提前量） |
| Health 数据提醒 | ❌ | ✅ 运动/睡眠/步数 |
| 饮食/运动提醒 | ❌ | ✅ |
| 工作/生活服务提醒 | ❌ | ✅ 通勤、快递、缴费 |
| 节日/纪念日 | ✅ 基础节日 | ✅ 自定义纪念日 |
| 心理关怀/家庭/宠物 | ❌ | ✅ |
| 灵动岛样式 | 1 种 | 5+ 种主题 |
| 提醒语气/人设 | 默认 | 多种人设可选 |
| AI 对话调整提醒 | ❌ | ✅ |
| 历史回顾 | 近 7 天 | 全部 |
| 数据导出 | ❌ | ✅ |

**设计原则：**
- 免费版让用户"感受到价值"但"有明确的功能天花板"
- 天气+时间作为免费入口（成本最低，覆盖最广）
- 所有需要 Health 数据 / 深度个性化的功能放在 Pro
- 灵动岛主题作为轻度付费驱动（视觉差异化）

## 5. 用户留存

### 5.1 留存驱动因素

| 因素 | 权重 | 说明 |
|------|------|------|
| 提醒精准度 | ⭐⭐⭐⭐⭐ | 核心价值，不准用户就卸载 |
| 提醒频率 | ⭐⭐⭐⭐ | 太多打扰，太少没价值 |
| 情感连接 | ⭐⭐⭐⭐ | 文案有人味，用户有情感依赖 |
| 功能成长 | ⭐⭐⭐ | 新功能上线给用户回访理由 |
| 灵动岛体验 | ⭐⭐⭐ | 视觉上好看，用着舒服 |

### 5.2 留存策略

#### 冷启动体验（Day 0-1）

1. **首次打开：** 极简引导（3 步以内），立即展示一条个性化提醒（基于当前时间+天气）
2. **权限引导：** 分步请求（先日历→再通知→最后 Health），每次请求前说明"为什么需要"
3. **首日体验：** 确保 Day 1 至少推送 3 条有价值的提醒

#### 新手期（Day 2-7）

1. **渐进式功能解锁：** Day 2 引入日历联动，Day 3 引入个性化调整
2. **微交互引导：** 对每条提醒可点"👍/👎"或"以后别推这种"，收集偏好
3. **周报推送：** Day 7 推送"第一周回顾"，展示提醒数据（你被提醒了 X 次，避免了 Y 件事）

#### 成熟期（Day 7+）

1. **提醒质量持续优化：** 基于用户反馈调整提醒类型/频率/时机
2. **功能迭代驱动回访：** V1.1 上线 Health 提醒，推送给所有用户
3. **情感运营：** 节日/纪念日/天气变化的特殊提醒，制造"被关心"的感觉

#### 留存指标目标

| 指标 | 目标值 |
|------|--------|
| D1 留存 | ≥ 55% |
| D7 留存 | ≥ 30% |
| D30 留存 | ≥ 15% |
| DAU/MAU | ≥ 25% |

### 5.3 召回策略

| 场景 | 召回方式 |
|------|----------|
| 7 天未打开 | 推送"最近天气变化大，回来看看你的提醒" |
| 14 天未打开 | 推送"新增了 XX 功能，来看看" |
| 30 天未打开 | 推送"好久不见，想念你"（低频，一次性的情感召回） |
| Pro 即将到期 | 提前 3 天推送续费提醒 |
| Pro 已过期 | 过期 7 天推送"限时 5 折回归" |

## 6. 成本模型

### 6.1 LLM API 成本

#### 方案选择

| 方案 | 模型 | 输入成本 | 输出成本 | 适用场景 |
|------|------|----------|----------|----------|
| 主力方案 | DeepSeek V3 / GLM-4 Flash | ¥1/百万 token | ¥1/百万 token | 日常提醒生成 |
| 降级方案 | 规则引擎 | ¥0 | ¥0 | 天气/时间类简单提醒 |
| 高级方案 | GPT-4o-mini | ¥2.4/百万 token | ¥9.6/百万 token | 复杂上下文提醒 |

#### 单次提醒成本估算

- 每次提醒生成：约 500 token 输入 + 100 token 输出
- 单次成本（DeepSeek/GLM）：约 0.0006 元/次
- 每用户每日 8 条 × 0.0006 = 0.0048 元/天
- 每用户每月 = 0.144 元

#### 按用户规模月成本估算

| 用户规模 | 日推送量 | LLM 成本/月 | 说明 |
---------|---------|------------|------|
| 1,000 | 8,000 | ¥144 | V1 上线初期 |
| 5,000 | 40,000 | ¥720 | 小规模增长 |
| 10,000 | 80,000 | ¥1,440 | 中等规模 |
| 50,000 | 400,000 | ¥7,200 | 规模化（含降级节省 30%） |
| 100,000 | 800,000 | ¥10,080 | 大规模（含缓存命中 40%） |

> 实际成本更低：规则引擎处理 40% 的推送（天气/时间类），LLM 仅处理需要个性化的场景。

## 8. 风险分析

### 8.1 风险矩阵

| 风险 | 概率 | 影响 | 等级 | 应对策略 |
------|------|------|------|----------|
| 用户觉得推送没用 | 中 | 致命 | 🔴 高 | 冷启动保守推送 + 快速学习 + 反馈机制 |
| 通知权限拒绝率高 | 高 | 高 | 🔴 高 | 先体验后权限 + 降级模式 + 二次引导 |
| LLM 成本超预期 | 低 | 中 | 🟡 中 | 规则引擎兜底 + 缓存 + 降级模型 |
| Apple 审核被拒 | 中 | 高 | 🔴 高 | 提前研究审核指南 + 准备降级方案 |
| Apple 加入类似功能 | 低 | 致命 | 🟡 中 | 速度优势 + 深度个性化 + 先发壁垒 |
| 竞品抄袭 | 高 | 中 | 🟡 中 | 先发 + 体验壁垒 + LLM 文案差异化 |
| 推送延迟过高 | 低 | 中 | 🟢 低 | 本地通知兜底 + 多级缓存 |
| 隐私政策合规风险 | 低 | 高 | 🟡 中 | 最小必要 + 数据本地化 + 法律咨询 |

### 8.2 核心风险应对

**风险1：用户觉得推送没用（最高优先级）**
- 冷启动前3天极保守（≤3条/天），宁可少推不要错推
- Day 1-7 快速收集反馈，有用率 < 30% 自动降低频率
- 连续3天有用率 < 10% 暂停推送，避免用户卸载

**风险2：通知权限拒绝率高**
- 先展示 Live Activity 效果，让用户看到价值后再要权限
- 拒绝后不立即再弹，等到 Day 2 温和引导
- 即使没有通知权限，App 内仍可查看提醒

**风险3：Apple 加入原生类似功能**
- Apple 通常做通用方案，不做深度个性化
- 我们的壁垒在于 LLM 文案温度 + 上下文融合深度
- 即使 Apple 做了，我们仍是"更好的提醒体验"
